# 设计方法应用要求

对每个纳入范围的接口,综合运用以下方法生成用例;每条用例必须标注 `design_method`。

## 1. 等价类划分

- 对每个参数建立有效等价类(类型正确、满足约束、业务合理)与无效等价类(类型错误、违反约束、业务非法)。
- 无效类逐参数单独覆盖(单变量法):一条用例只破坏一个参数,其余参数保持有效值。
- 必填参数缺失必须有用例;可空参数不强制。
- 有效等价类合并:一个"正常成功"用例可同时覆盖全部参数的有效类。

## 2. 边界值分析

- 数值参数(minimum/maximum):至少取 min、max 各一条有效,越界(min-1、max+1)各一条无效。
- 字符串长度(min_length/max_length):长度等于 max 一条有效,超过 max 一条无效;有 min_length 时取一条最短有效、一条不足 min 无效。
- 边界用例过多时按优先级截断,优先保留越界无效用例。

## 3. 场景法

- 对资源型接口(REST CRUD)设计业务流场景链:创建 → 查询 → 更新 → 删除 → 复查已删除,串联多个接口。
- 有登录态的接口:设计"注册 → 登录 → 携 token 访问"的主流程场景。
- 场景用例的 steps 必须分步描述每一步的请求与预期。

## 4. 因果图 / 判定表

- 存在 ≥2 个可选条件参数(筛选、开关、状态、枚举组合)的接口,列出条件组合判定表。
- 组合选取规则:全默认、单条件逐个生效、条件间互斥/约束组合(如 min>max)、典型业务组合;组合总数超过 8 条时按业务意义截断。
- 互斥/约束组合(如"最低价不能大于最高价")必须有用例。

## 5. 异常与鉴权

- 需要鉴权的接口:未携带 token、携带无效 token 各至少一条。
- 资源不存在(路径参数 id 无效)至少一条。
- 重复/冲突类业务错误(如重复注册)按接口 business_errors 覆盖。

# 优先级定义

- P0:核心成功路径、鉴权失败(未登录)、参数校验失败(必填缺失)。每个接口至少 1 条 P0。
- P1:业务错误(资源不存在、重复冲突、错误凭据)、常见无效等价类。
- P2:边界值越界、类型错误、枚举非法。
- P3:组合判定表中的次要组合、极端长度/数值。

# 数量与截断

- 单接口用例数建议 6~14 条;超出时按 P0 > P1 > P2 > P3 保留。
- 所有请求体参数必须给出可直接执行的值,禁止使用占位符。
