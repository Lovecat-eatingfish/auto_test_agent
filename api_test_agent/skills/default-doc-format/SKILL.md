# 用例编号规则

- 格式:`项目码-模块码-三位序号`,如 `DEMO-USER-001`。
- 项目码:由 Agent 按项目名生成,全大写。
- 模块码:接口所属业务模块,全大写字母(如 USER、PRODUCT、AUTH)。
- 序号:模块内从 001 递增,禁止跳号。

# 字段定义

| 列 | 说明 |
| --- | --- |
| 用例编号 | 全局唯一,按上述规则 |
| 所属模块 | 模块中文名或英文标识 |
| 用例标题 | 一句话说清验证点,含接口与场景 |
| 优先级 | P0 / P1 / P2 / P3 |
| 设计方法 | 等价类 / 边界值 / 场景法 / 因果图 之一 |
| 前置条件 | 执行前需满足的状态(如"已存在用户 admin") |
| 测试步骤 | 分步描述,每步含请求方法、路径与关键数据 |
| 测试数据 | 关键请求参数/请求体(可直接执行) |
| 预期结果 | 状态码 + 业务码 + 关键字段断言,可被自动化校验 |
| 实际结果 | 由 Agent 自测后回填;人工执行时手工填写 |
| 执行状态 | 未执行 / 通过 / 失败 |
| 关联自动化用例 | pytest 用例 node id,由 Agent 生成脚本后回填 |

# 文档格式

- Excel:首行表头加粗、冻结首行;每模块用例连续排列;另含"测试概览"与"接口清单"两个 sheet。
- Markdown:与 Excel 同构,顶部为概览,按模块分节列用例表格。
