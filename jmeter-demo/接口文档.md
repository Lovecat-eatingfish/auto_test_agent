# jmeter-demo 接口文档

> 版本：1.0（JWT + SQLite）　更新日期：2026-10-02

## 1. 基本信息

| 项目 | 说明 |
|---|---|
| Base URL | `http://localhost:38000` |
| 传输格式 | JSON（`Content-Type: application/json`） |
| 字符编码 | UTF-8 |
| 鉴权方式 | JWT，请求头 `Authorization: Bearer <token>` |
| token 有效期 | 默认 7200 秒（2 小时），由 `jwt.expire-minutes` 配置 |

**统一响应信封**：所有接口（含业务失败）均返回 HTTP 200 + 业务码：

```json
{"code": 0, "msg": "ok", "data": ...}
```

- `code = 0` 表示成功；非 0 为业务失败，`data` 为 `null`
- 只有参数不是合法 JSON、请求体缺失等框架级错误才返回 HTTP 400/500

## 2. 鉴权说明

1. 先调 `POST /login` 拿 token；
2. 之后的业务请求在请求头带 `Authorization: Bearer <token>`；
3. 需要鉴权的接口：`GET /user/{id}`、`GET /users`、`POST /order`；
   开放接口：`POST /login`、`GET /ping`、`GET /slow`、`GET /stats`。

**种子账号**：`user1` ~ `user1000`，密码统一 `123456`。

## 3. 接口详情

### 3.1 登录　`POST /login`（开放）

校验用户名密码，签发 JWT。用户不存在与密码错误返回同一提示（不暴露账号是否存在）。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 用户名 |
| password | string | 是 | 密码 |

**请求示例**

```json
{"username": "user1", "password": "123456"}
```

**成功响应**

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxIiwidXNlcm5hbWUiOiJ1c2VyMSIsImlhdCI6MTc5MDkxMDA1NSwiZXhwIjoxNzkwOTE3MjU1fQ.s0P6on79sNCutMNEzsd-sYHxz1m5gt1ML9xma__Lu5Q",
    "tokenType": "Bearer",
    "expiresIn": 7200,
    "userId": 1,
    "username": "user1"
  }
}
```

**可能业务码**：`4001`（username/password 缺失）、`4010`（用户名或密码错误）

---

### 3.2 基准接口　`GET /ping`（开放）

无业务逻辑、不查库，用于测框架本身开销。

**响应示例**

```json
{"code": 0, "msg": "ok", "data": "pong"}
```

---

### 3.3 用户详情　`GET /user/{id}`（需要 token）

按 id 查单个用户，SQLite 点查。

**路径参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| id | long | 用户 id，种子数据范围 1~1000 |

**请求示例**

```bash
curl -H "Authorization: Bearer <token>" http://localhost:38000/user/1
```

**成功响应**

```json
{"code": 0, "msg": "ok", "data": {"id": 1, "name": "用户1", "balance": 100.0}}
```

**可能业务码**：`4011`/`4012`（token 问题）、`4040`（用户不存在）

---

### 3.4 用户列表　`GET /users?size=100`（需要 token）

批量查询用户，`size` 控制响应体大小。

**Query 参数**

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| size | int | 否 | 10 | 返回条数，超出按 1000 截断 |

**成功响应**（`size=2` 时）

```json
{
  "code": 0,
  "msg": "ok",
  "data": [
    {"id": 1, "name": "用户1", "balance": 100.0},
    {"id": 2, "name": "用户2", "balance": 100.0}
  ]
}
```

**可能业务码**：`4011`/`4012`（token 问题）

---

### 3.5 下单　`POST /order`（需要 token）

写库：校验用户存在 + 插入 orders 表（语句各自自动提交，返回数据库自增 orderId）。

**请求体**

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| userId | number | 是 | — | 下单用户 id（1~1000） |
| product | string | 否 | 默认商品 | 商品名 |
| quantity | int | 否 | 1 | 数量 |

**请求示例**

```json
{"userId": 1, "product": "apple", "quantity": 3}
```

**成功响应**

```json
{
  "code": 0,
  "msg": "ok",
  "data": {"orderId": 1, "userId": 1, "product": "apple", "quantity": 3}
}
```

**可能业务码**：`4001`（userId 缺失）、`4002`（用户不存在）、`4011`/`4012`（token 问题）

---

### 3.6 慢接口　`GET /slow?ms=200`（开放）

人为阻塞 `ms` 毫秒（不查库），用于测线程池排队、超时场景。

**Query 参数**

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| ms | long | 否 | 200 | 阻塞毫秒数，超出按 5000 截断 |

**响应示例**

```json
{"code": 0, "msg": "ok", "data": "slept 200ms"}
```

---

### 3.7 统计　`GET /stats`（开放）

查看各接口累计请求数与库内订单总数，压测完核对有无丢请求。

**响应示例**

```json
{"code": 0, "msg": "ok", "data": {"/ping": 0, "/user": 1, "/order": 1, "db_orders": 1}}
```

> 注意：`/ping`、`/user`、`/order` 是内存计数，**重启清零**；`db_orders` 来自数据库，**持久保留**。

## 4. 业务码一览

| code | 含义 | 触发场景 |
|---|---|---|
| 0 | 成功 | — |
| 4001 | 参数缺失 | login 缺 username/password；order 缺 userId |
| 4002 | 用户不存在 | order 的 userId 在库中查不到 |
| 4010 | 用户名或密码错误 | 登录失败 |
| 4011 | token 缺失或无效 | 请求头没有 `Authorization: Bearer ...`，或 token 被篡改/签名不符 |
| 4012 | token 已过期 | token 超过有效期 |
| 4040 | 用户不存在 | /user/{id} 查不到该 id |

## 5. 数据说明

- 数据库：SQLite，文件 `data/demo.db`（启动目录下），WAL 模式
- `users(id, username, password, name, balance)`：种子 1000 条，账号 `user1`~`user1000`，密码 `123456`
- `orders(id, user_id, product, quantity, created_at)`：由 POST /order 写入，自增主键
- **重置数据**：停止服务 → 删除 `data/demo.db`（连同 `-wal`/`-shm`）→ 重启，种子数据会自动重新灌入
